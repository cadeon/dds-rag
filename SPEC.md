# Dewey Decimal RAG System

## Overview

A retrieval-augmented generation (RAG) system that uses Dewey Decimal Classification (DDC) numbers as a hierarchical routing layer to improve retrieval precision and reduce token waste. Documents are classified into DDC categories at ingest time, and queries are routed to relevant branches before vector search.

## Architecture

### Three-Layer Retrieval Funnel

```
Query → DDC Classification → Abstract Matching → Vector Search → Full Text
```

1. **DDC Routing Layer**: Query is classified into a DDC number, narrowing the search space from the full corpus to a single branch (e.g., 100K docs → ~200 in 516.x).
2. **Abstract Matching**: Lightweight similarity check against document summaries within the DDC branch (short text, fast comparison).
3. **Vector Search**: Embedding-based retrieval on the filtered subset for semantic matching.
4. **Full Text**: Only the top N candidates have their full text retrieved for the final answer.

### Ingest Pipeline

```
Document → Summarize (100 words) → Classify (DDC number) → Embed (vector) → Store
```

Each document gets:
- **Summary**: 50-100 word abstract generated by LLM at ingest
- **DDC Number**: Most specific classification (e.g., 516.37)
- **Vector Embedding**: Semantic representation of the full text
- **Full Text**: Chunked and stored for retrieval

### Storage Schema

```yaml
document:
  id: string
  ddc_number: float          # e.g. 516.37
  ddc_parent: float          # e.g. 510 (for fallback)
  summary: string            # 50-100 words
  embedding: vector          # document-level embedding
  chunks:
    - id: string
      text: string
      embedding: vector
      offset: int
```

## Components

### 1. DDC Classifier

Classifies documents and queries into Dewey Decimal numbers.

**Input**: Document text or query string
**Output**: DDC number + confidence score + justification

**Implementation Options**:
- **LLM-based** (initial): Prompt-based classification using an LLM with DDC schema
- **Trained classifier** (production): Fine-tuned lightweight model trained on LLM-labeled data
- **Hybrid**: LLM for low-confidence cases, trained model for high-confidence

**Prompt Template**:
```
Classify this document into the most specific Dewey Decimal Classification number.
Available main classes:
000 - Computer science, information & general works
100 - Philosophy & psychology
200 - Religion
300 - Social sciences
400 - Language
500 - Pure science
600 - Technology
700 - Arts & recreation
800 - Literature
900 - History & geography

Document: {document_text}

Return: DDC number, confidence (0-1), and one-sentence justification.
```

### 2. Query Router

Routes incoming queries through the retrieval funnel.

**Flow**:
1. Classify query into DDC number
2. Retrieve documents in that DDC branch (and adjacent branches if confidence < threshold)
3. Match query against document summaries within branch
4. Run vector search on top summary matches
5. Return ranked results with full text chunks

**Fallback Strategy**:
- If DDC confidence < 0.7: search parent class (e.g., 510 instead of 516.37)
- If no results in branch: expand to sibling branches
- If still no results: full corpus vector search

### 3. Document Summarizer

Generates abstracts for ingested documents.

**Input**: Full document text
**Output**: 50-100 word summary capturing core subject and key points

**Purpose**: Provides a compressed, noise-free representation for fast routing and matching.

### 4. Embedding Service

Generates vector embeddings for documents and queries.

**Requirements**:
- Supports both document-level and chunk-level embeddings
- Configurable embedding model (e.g., text-embedding-3-small, BGE, etc.)

## Configuration

```yaml
# config.yaml
ddc:
  confidence_threshold: 0.7    # minimum confidence for DDC routing
  fallback_parent: true        # fall back to parent class if confidence low
  expand_siblings: true        # search sibling branches if no results
  max_branch_results: 50       # max documents to consider per branch

summarizer:
  model: string               # LLM model for summarization
  max_length: 100             # max words in summary
  temperature: 0.1

embedding:
  model: string               # embedding model
  dimensions: int             # embedding dimensions

retrieval:
  top_k: 10                   # final results to return
  abstract_top_k: 20          # abstract matches to consider before vector search
  chunk_size: 500             # tokens per chunk
  chunk_overlap: 50           # overlap between chunks

storage:
  type: string                # "sqlite", "postgres", "chroma", etc.
  path: string                # database path or connection string
```

## API

### Ingest

```python
# Add a single document
def ingest_document(text: str) -> Document:
    """Ingest a document: summarize, classify, embed, and store."""
    summary = summarizer.summarize(text)
    ddc = classifier.classify(text)
    embedding = embedder.embed(text)
    chunks = chunker.chunk(text)
    return storage.save(Document(text, summary, ddc, embedding, chunks))

# Batch ingest
def ingest_batch(documents: list[str]) -> list[Document]:
    """Ingest multiple documents with parallel processing."""
    return [ingest_document(doc) for doc in documents]
```

### Query

```python
# Search with DDC routing
def query(text: str, top_k: int = 10) -> list[Result]:
    """Route query through DDC funnel and return ranked results."""
    ddc = classifier.classify(text)
    candidates = storage.search_by_ddc(ddc.number)
    abstract_matches = rank_by_abstract(text, candidates)
    vector_matches = rank_by_embedding(text, abstract_matches[:retrieval.abstract_top_k])
    return vector_matches[:top_k]

# Search with explicit DDC override
def query_ddc(text: str, ddc_number: float, top_k: int = 10) -> list[Result]:
    """Search within a specific DDC branch."""
    candidates = storage.search_by_ddc(ddc_number)
    return rank_by_embedding(text, candidates)[:top_k]
```

### Admin

```python
# Get classification statistics
def get_ddc_distribution() -> dict[float, int]:
    """Return document count per DDC number."""
    return storage.ddc_distribution()

# Re-classify a document
def reclassify(document_id: str, new_ddc: float) -> Document:
    """Manually override DDC classification."""
    return storage.update_ddc(document_id, new_ddc)
```

## Multi-Classification Handling

Documents that span multiple DDC categories are tagged with all relevant numbers. The classifier returns a list of (ddc_number, confidence) pairs. All are stored and used for routing.

Example:
```yaml
document_id: doc_123
ddc_classifications:
  - number: 170    # moral philosophy
    confidence: 0.9
  - number: 006.7  # AI
    confidence: 0.85
  - number: 324.8  # civil liberties
    confidence: 0.7
```

## Consistency & Maintenance

- **Cluster analysis**: Periodically analyze documents in the same DDC branch for classification consistency
- **Normalization**: If >70% of documents in a cluster share a more specific number, standardize to that number
- **Gap detection**: Identify DDC branches with no documents to spot coverage gaps
- **Human review**: Flag low-confidence classifications (<0.5) for manual review

## Future Considerations

- **Custom DDC extensions**: Support for domain-specific subcategories beyond standard DDC
- **Faceted classification**: Supplement DDC with additional metadata tags (author, date, language, format)
- **Cross-lingual**: DDC numbers are language-agnostic, enabling multilingual RAG
- **Incremental reclassification**: Re-classify documents when new related content is ingested
